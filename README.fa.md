# داشبورد نمایندگی PVNetwork برای 3x-ui

> 🇬🇧 [English version](README.md) | 🇮🇷 فارسی

[![نصب](https://img.shields.io/badge/نصب-یک%20خط-10615b)](#-نصب-سریع)

داشبورد نمایندگی سلف‌هاست‌شده برای یک یا چند سرور 3x-ui موجود — پول ترافیک، مدیریت چندپنلی، فروش با ربات میرزا، برند اختصاصی، ورود دومرحله‌ای، پرتال سابسکریپشن و حسابداری سخت‌گیرانه.

## ⚡ نصب سریع

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/DashSaman/PVNetwork-Reseller-Dashboard/main/install.sh)
```

همین یک خط. نصب‌کننده نام دامنهٔ پنل را می‌پرسد، Docker، Apache TLS، Let's Encrypt و دیتابیس را خودکار راه می‌اندازد — بدون دست‌زدن به سرورهای 3x-ui، Xray یا سرویس‌های دیگر شما.

**افزایش گروهی حجم و زمان:** در بخش نماینده‌ها، کنار نمایندهٔ موردنظر «افزایش گروهی» را بزنید. گیگ و روز اضافه برای هر کاربر را وارد کنید، پیش‌نمایش تعداد کاربران و حجم لازم را ببینید و سپس تأیید کنید. حجم از موجودی فعلی پول همان نماینده تخصیص می‌یابد؛ سقف پول افزایش نمی‌یابد. اگر موجودی کافی نباشد یا یکی از پنل‌های لازم در دسترس نباشد، عملیات شروع نمی‌شود. مصرف، شناسه‌های اتصال و وضعیت فعال/غیرفعال حفظ می‌شوند. صفر یعنی بدون تغییر؛ حجم/زمان نامحدود، نامحدود می‌ماند و زمان کاربران منقضی‌شده از انقضای قبلی افزایش می‌یابد. عملیات ناقص، رزرو سهمیه را حفظ می‌کند و با «ادامهٔ همین عملیات» بدون افزایش دوباره قابل تکمیل است؛ حتی پس از بستن صفحه یا راه‌اندازی مجدد پنل. اگر پاسخ پنل گم شود و هم‌زمان اشتراک مدت‌دار با اولین اتصال فعال شود، سیستم به‌جای حدس‌زدن و افزایش دوبارهٔ احتمالی، برای بررسی زمان همان کاربر متوقف می‌شود. این قابلیت فقط برای ادمین و کاربران همان نماینده است.

## 🛡️ امنیت و حسابداری

| قابلیت | وضعیت |
|---|---|
| نمایندهٔ محدود → کاربر نامحدود | ✅ غیرممکن (server-side) |
| دور زدن پول (حذف/ریست/ساخت مجدد) | ✅ مسدود (مصرف قطعی) |
| over-spend هم‌زمان | ✅ قفل اتمیک |
| شکست جزئی چندپنلی | ✅ ژورنال عملیات + retry |
| حسابداری crash-safe | ✅ commit در یک تراکنش |
| Idempotency ساخت | ✅ هدر `Idempotency-Key` |
| رزرو دلتای ویرایش | ✅ ماندگار |
| مصرف کانونی چندپنلی | ✅ تک‌منبع |
| تصادم subId | ✅ ایندکس یکتا |
| حذف ناامن نماینده | ✅ 409 |
| پول زیر تعهدات | ✅ 409 + override صریح |

## افزایش گروهی و بکاپ

[گزارش خطای همگام‌سازی نود در ۱۷ اکتبر ۲۰۲۶](docs/incidents/2026-10-17-stale-node-client-state.md) شامل علت تأییدشده، اصلاح نصب‌شده و نتیجهٔ موفق تست ساخت و تمدید هر سه نماینده است. برای رخداد مشابه، ابتدا همین سابقه را بخوانید.

### افزایش گروهی حجم و زمان

نماینده در «کاربران من ← افزایش گروهی حجم و زمان» می‌تواند گیگ و روز اضافه برای تمام کاربران خودش تعیین کند. ادمین هم همین عملیات را از ردیف هر نماینده انجام می‌دهد. پیش‌نمایش تعداد کاربران و مجموع حجم را نشان می‌دهد؛ حجم از موجودی فعلی پول نماینده تخصیص می‌یابد و سقف پول افزایش نمی‌یابد. مصرف، شناسهٔ اتصال و وضعیت فعال/غیرفعال حفظ می‌شوند. اجرای ناقص از ژورنال ماندگار ادامه پیدا می‌کند و کاربران موفق دوباره شارژ نمی‌شوند.

### بکاپ روزانه و انتقال داشبورد

در نسخهٔ Docker جدید، دکمهٔ «بازیابی بکاپ» در تب بکاپ ادمین اصلی وجود دارد.
فقط روی نصب تازه (بدون نماینده، کاربر، اتصال پنل، تنظیمات و ژورنال قبلی) فعال
است. ZIP حداکثر ۶۴ مگابایت را آپلود کنید؛ پس از بررسی ساختار، checksum، SQLite،
سازگاری schema و رمزگشایی تنظیمات، خلاصه نمایش داده می‌شود. برای اجرای بازیابی،
رمز فعلی ادمین مقصد و کد دومرحله‌ای در صورت فعال‌بودن لازم است. فقط داشبورد
دوباره اجرا می‌شود و دیتابیس و کلید پیش از شروع برنامه نصب می‌شوند؛ سپس با
حساب‌های داخل بکاپ وارد شوید. مسیر خصوصی نودهای سرور قبلی را روی مقصد بررسی کنید.

[راهنمای کامل بازیابی روی سرور جدید](docs/dashboard-migration-restore.fa.md) شامل بررسی پورت و شبکه، نصب کلید اصلی، تنظیم مسیر امن نود، آزمون پذیرش، جابه‌جایی دامنه و برگشت امن است. پیش از انتقال واقعی آن را بخوانید.

در پنل ادمین اصلی، تب «بکاپ» امکان تهیه و دانلود ZIP را دارد. فایل شامل تمام دیتابیس داشبورد (نماینده‌ها، کاربران و subId، موجودی و مصرف، دسترسی‌ها، برند و دامنه، گزارش‌ها، اتصال‌های ذخیره‌شده و اطلاعات رمزنگاری‌شده) و `APP_SECRET` لازم برای بازیابی است. بکاپ با SQLite backup API و بررسی integrity تهیه می‌شود، شامل تغییرات committed در WAL است و checksum همهٔ فایل‌ها پیش از انتشار کنترل می‌شود. بکاپ با پنل پیکنیکی یا سایر پنل‌های خارجی تماس نمی‌گیرد و دیتابیس زندهٔ آن‌ها جزو این فایل نیست.

نصب‌کننده فقط تایمر اختصاصی `pv-reseller-backup.timer` را فعال می‌کند: هر روز **۰۳:۰۰ به وقت تهران**. ZIPهای همین بخش در `/opt/pv-reseller/data/backups` نگهداری می‌شوند و فایل‌های مدیریت‌شده‌ای که بیش از **۵ روز** عمر دارند، پس از تهیهٔ بکاپ جدید حذف می‌شوند. بکاپ‌های استقرار در `/opt/pv-reseller/backup` و فایل‌های سرویس‌های دیگر مشمول حذف نیستند. برای انتقال یا نگهداری خارج از سرور، فایل را دانلود و در محل امن نگه دارید؛ حاوی اطلاعات محرمانه و کلید بازیابی است.

روی مقصد تازه، ابتدا فایل را اعتبارسنجی و در پوشهٔ خالی بازیابی کنید:

```bash
python3 scripts/panel-backup.py verify /secure/pvnet-backup.zip
python3 scripts/panel-backup.py restore /secure/pvnet-backup.zip /secure/pvnet-restored
```

خروجی `data/custom.db`، `recovery.env` و manifest است. مقصد غیرخالی رد می‌شود. روی سرور جدید، فقط پس از توقف داشبورد تازه و بکاپِ دادهٔ مقصد، فایل DB را به volume داشبورد منتقل و مقدار `APP_SECRET` را از `recovery.env` در تنظیمات همان داشبورد قرار دهید؛ کلید تازه نسازید، چون رمزهای ذخیره‌شده با کلید اصلی باز می‌شوند. دامنه، DNS و TLS سرور مقصد جداگانه تنظیم می‌شوند. حساب‌های داشبورد و اتصال به پنل‌های خارجی موجود حفظ می‌شود؛ انتقال خود سرورهای VPN عملیات جداگانه‌ای است.

```bash
systemctl list-timers pv-reseller-backup.timer
journalctl -u pv-reseller-backup.service -n 20 --no-pager
# فعال‌سازی روی نصب موجود، پس از به‌روزرسانی image داشبورد:
bash /opt/pv-reseller/app/scripts/install-backup-timer.sh
```

## 🔄 به‌روزرسانی

```bash

```
