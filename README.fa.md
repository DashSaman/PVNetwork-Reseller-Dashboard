# داشبورد نمایندگی PVNetwork برای پنل 3x-ui

> 🇬🇧 English version of this document: [README.md](README.md)

PVNetwork یک داشبورد نمایندگی (ایجنت) سلف‌هاست‌شده برای یک یا چند سرور 3x-ui موجود است. به صاحب سامانه یک پنل ادمین مرکزی می‌دهد برای مدیریت نماینده‌ها، پول ترافیک، دسترسی اینباندها، کاربران، برند و دامنه اختصاصی، ورود دومرحله‌ای، گزارش فعالیت‌ها، لینک سابسکریپشن، QR کد و عملیات مرتبط.

![نمای کلی داشبورد](docs/screenshots/02-admin-overview.png)

> نصب‌کننده پیش‌فرض فقط **داشبورد** را نصب می‌کند؛ 3x-ui، Xray یا Caddy نصب نمی‌شود و هیچ سرویس دیگری که روی سرور در حال کار است را جایگزین نمی‌کند.

## شروع سریع

به‌عنوان `root` روی اوبونتو یا دبیان اجرا کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/DashSaman/PVNetwork-Reseller-Dashboard/main/install.sh)
```

نصب‌کننده نام هاست پنل را می‌پرسد، برای مثال:

```text
npanel.example.com
```

و در صورت تمایل نام کاربری ادمین. سپس:

- پیش از هر تغییر مخرب، وضعیت پورت و نصب قبلی را بررسی می‌کند؛
- فقط وابستگی‌های جاافتاده سیستم را نصب می‌کند؛
- از نصب Docker موجود استفاده می‌کند یا در نبود آن Docker را نصب می‌کند؛
- اپلیکیشن را در `/opt/pv-reseller/app` کلون می‌کند؛
- دیتای SQLite دائمی را در `/opt/pv-reseller/data` نگه می‌دارد؛
- بکاپ‌ها را در `/opt/pv-reseller/backup` ذخیره می‌کند؛
- یک کانتینر Docker به نام `pv-reseller-dashboard` می‌سازد؛
- اپ را فقط روی `127.0.0.1:31080` منتشر می‌کند؛
- از Apache موجود استفاده می‌کند یا در نبودش Apache نصب می‌کند؛
- یک vhost اختصاصی اضافه می‌کند بدون غیرفعال‌کردن vhostهای دیگر؛
- گواهی Let's Encrypt را با اعتبارسنجی webroot Certbot می‌گیرد؛
- پس از در دسترس نگه‌داشتن مسیر ACME، HTTP را به HTTPS ریدایرکت می‌کند؛
- پیش از اعلام اتمام، سلامت HTTP محلی، HTTPS مبدا و API را بررسی می‌کند.

به Docker Compose نیازی نیست.

## نیازمندی‌ها

- اوبونتو یا دبیان
- دسترسی root
- حداقل ۴ گیگابایت فضای خالی برای بیلد اولیه ایمیج
- یک نام هاست مثل `npanel.example.com`
- DNS آن نام هاست باید به این سرور برسد — مستقیم یا از طریق Cloudflare
- پورت‌های ۸۰ و ۴۴۳ باید برای Apache آزاد باشند یا در اختیار سرویس Apache موجود باشند

خود اپلیکیشن مستقیماً به اینترنت منتشر نمی‌شود. Docker فقط این‌طور بایند می‌شود:

```text
127.0.0.1:31080 -> pv-reseller-dashboard:3000
```

Apache نقطه ورود عمومی HTTPS است.

## معماری

```text
Browser / Cloudflare
        |
        v
   Apache :80/:443
        |
        v
 127.0.0.1:31080
        |
        v
 pv-reseller-dashboard
        |
        +---- API ----> سرور(های) خارجی 3x-ui موجود
        |
        +---- SQLite --> /opt/pv-reseller/data/custom.db
```

این داشبورد چرخه حیات سرورهای 3x-ui/Xray شما را مدیریت نمی‌کند. بعد از نصب، آن‌ها را از خود داشبورد اضافه کنید.

## Cloudflare

پروکسی Cloudflare پشتیبانی می‌شود و نصب‌کننده به توکن API کلادفلر نیازی ندارد.

تنظیمات پیشنهادی برای نام هاست داشبورد بعد از سالم‌بودن HTTPS مبدا:

- Proxy status: **Proxied** (ابر نارنجی)
- SSL/TLS encryption mode: **Full (strict)**
- Always Use HTTPS: روشن
- قانون کش برای نام هاست داشبورد: **Bypass cache**
- Rocket Loader: اگر با جاوااسکریپت داشبورد تداخل دارد، برای این نام هاست خاموش کنید

اگر صدور گواهی در حالت پروکسی‌شده شکست خورد، بررسی کنید درخواست‌های HTTP به `/.well-known/acme-challenge/` به مبدا می‌رسند یا نه.

## اطلاعات ورود اولیه

در نصب اول، اسکریپت `APP_SECRET` و رمز ادمین تصادفی و امن تولید می‌کند و در این فایل‌ها نگه می‌دارد:

```text
/opt/pv-reseller/.env
/opt/pv-reseller/INITIAL_CREDENTIALS.txt
```

فایل دوم فقط جنبه ثبت تاریخچه دارد. اگر رمز ادمین بعداً داخل داشبورد عوض شود، رمز جدید در این فایل‌ها نوشته **نمی‌شود**.

## به‌روزرسانی

همان دستور یک‌خطی را دوباره اجرا کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/DashSaman/PVNetwork-Reseller-Dashboard/main/install.sh)
```

یا از داخل یک نصب موجود:

```bash
bash /opt/pv-reseller/app/update.sh
```

به‌روزرسانی این‌ها را حفظ می‌کند:

- `/opt/pv-reseller/.env`
- `APP_SECRET`
- مقدار اولیه رمز نصب‌کننده
- دیتابیس SQLite
- دامنه پنل و پورت انتخابی

پیش از جایگزینی داشبورد در حال اجرا، نصب‌کننده از دیتابیس و پیکربندی بکاپ می‌گیرد. سپس **مایگریشن‌های فقط-افزودنی** را روی دیتابیس SQLite اعمال می‌کند (فقط ستون جدید اضافه می‌شود؛ هیچ داده‌ای حذف یا بازنویسی نمی‌شود — ستون‌های اعمال‌شده قبلی دوباره اعمال نمی‌شوند)، ایمیج کاندید را در حالی که کانتینر فعلی در حال کار است می‌سازد و فقط کانتینر `pv-reseller-dashboard` را جایگزین می‌کند. اگر کانتینر جدید چک سلامت را رد کند و ایمیج قبلی موجود باشد، ایمیج قبلی برگردانده می‌شود.

هیچ کانتینر Docker نامرتبط، Xray، 3x-ui، دیتابیس یا سرویس VPN دیگری ری‌استارت نمی‌شود.

## بکاپ و بازگردانی

بکاپ‌ها اینجا ساخته می‌شوند:

```text
/opt/pv-reseller/backup/YYYYMMDD-HHMMSS/
```

می‌توانند شامل این‌ها باشند:

- `custom.db`
- `.env`
- `.installer-env`
- فایل‌های vhost آپاچی داشبورد

برای بازگردانی دستی دیتابیس، فقط کانتینر داشبورد را متوقف کنید، `/opt/pv-reseller/data/custom.db` را با بکاپ دلخواه جایگزین کنید و کانتینر را با همان `.env` و بایند loopback دوباره بسازید.

## اتصال سرور 3x-ui خارجی

بعد از ورود به داشبورد:

1. **تنظیمات / پنل‌ها** را باز کنید.
2. **افزودن پنل جدید** را بزنید.
3. یک نام نمایشی برای سرور وارد کنید.
4. آدرس کامل وب 3x-ui موجود را — همراه با base path در صورت وجود — وارد کنید.
5. یا API Token پنل یا نام کاربری/رمز مدیر را وارد کنید.
6. در صورت تمایل آدرس پایه سابسکریپشن و مسیر ساب را تنظیم کنید.
7. **تست اتصال** را بزنید.
8. پنل را ذخیره کنید.
9. به **نماینده‌ها** بروید و نماینده بسازید/ویرایش کنید. لیست اینباندها هنگام باز شدن تب نماینده‌ها به‌روز می‌شود.

چند سرور 3x-ui خارجی را می‌توان اضافه کرد. اندپوینت `/api/admin/inbounds` اینباندهای همه را تجمیع می‌کند.

## امکانات اصلی

- چند پنل 3x-ui
- دسترسی اینباند به تفکیک نماینده
- پول ترافیک برای هر نماینده
- ساخت کاربر مولتی‌لوکیشن
- **ورودی‌های عددی سازگار با موبایل**: فیلدهای سهمیه ترافیک (گیگ)، تعداد و تعداد دستگاه هم ارقام فارسی و هم لاتین را می‌پذیرند، در گوشی آزادانه پاک و دوباره تایپ می‌شوند و دکمه‌های پیشنهادی دارند (۵، ۱۰، ۱۵، ۲۰، **۳۰، ۴۰**، ۵۰، ۱۰۰ گیگ)
- برند و دامنه اختصاصی (وایت‌لیبل)
- پرتال سابسکریپشن کاربر نهایی و QR کد
- ساخت گروهی کاربر
- مشاهده مصرف و انقضا
- خروجی CSV
- اعلان‌های تلگرام نماینده
- **اتصال ربات میرزا پنل** با دو قابلیت:
  - اعلان‌ها: بات تلگرامی خود نماینده (مثلاً بات سرویس میرزا پنل) به‌عنوان کانال دوم اعلان — ساخت کاربر، مصرف ۸۰٪ به بالا و انقضای نزدیک
  - **فروش مستقیم از طریق پل سازگار با 3x-ui**: ربات میرزا دقیقاً مثل اتصال به یک پنل 3x-ui به همین داشبورد وصل می‌شود (آدرس پنل + نام کاربری/رمز داشبورد نماینده)؛ ربات به اینباندهای مجاز و سقف پول ترافیک همان نماینده محدود است و همه عملیاتش از همان قوانین داشبورد عبور می‌کند
- **ضد دور زدن پول ترافیک**: حذف یا ریست ترافیک یک کاربر، مصرف واقعی او را به‌صورت قطعی از پول نماینده کم می‌کند — نماینده نمی‌تواند با حذف و ساخت مجدد کاربر، حجم مصرف‌شده را بازیابی کند
- ورود دومرحله‌ای TOTP ادمین و نماینده
- محدودسازی نرخ ورود
- گزارش فعالیت‌ها

## ساختار نصب

```text
/opt/pv-reseller/
├── app/                    # سورس (git checkout)
├── data/
│   └── custom.db           # دیتابیس SQLite دائمی
├── backup/                 # بکاپ‌های زمان‌دار آپدیت
├── .env                    # مقادیر بوت‌استرپ ادمین/APP_SECRET (0600)
├── .installer-env          # متادیتای غیرمحریم نصب‌کننده
└── INITIAL_CREDENTIALS.txt # ثبت نصب اول (0600)
```

منابع Docker که نصب‌کننده پیش‌فرض می‌سازد:

```text
container: pv-reseller-dashboard
network:   pv_reseller_net
image:     pv-reseller-dashboard:local
bind:      127.0.0.1:31080:3000
```

## نصب غیرتعاملی

برای اتوماسیون، مقادیر را با متغیر محیطی بدهید:

```bash
PANEL_DOMAIN=npanel.example.com \
ADMIN_USERNAME=admin \
APP_PORT=31080 \
bash <(curl -fsSL https://raw.githubusercontent.com/DashSaman/PVNetwork-Reseller-Dashboard/main/install.sh)
```

| متغیر | پیش‌فرض | معنی |
|---|---:|---|
| `PANEL_DOMAIN` | پرسش در نصب | نام هاست عمومی داشبورد |
| `ADMIN_USERNAME` | `admin` | نام کاربری ادمین اولیه (فقط نصب اول) |
| `APP_PORT` | `31080` | پورت لوکال Docker |
| `INSTALL_DIR` | `/opt/pv-reseller` | ریشه نصب |

## متغیرهای محیطی اپلیکیشن

| متغیر | پیش‌فرض | معنی |
|---|---|---|
| `DATABASE_URL` | `file:/app/data/custom.db` | دیتابیس SQLite داخل کانتینر |
| `APP_SECRET` | تولید خودکار | کلید رمزنگاری نشست/رمزها |
| `ADMIN_USERNAME` | `admin` | نام کاربری بوت‌استرپ ادمین |
| `ADMIN_PASSWORD` | تولید خودکار | رمز بوت‌استرپ — فقط هنگام ساخت اولین ردیف ادمین |
| `PORT` | `3000` | پورت داخلی Next.js |

## عیب‌یابی

### داشبورد محلی سالم است ولی آدرس عمومی جواب نمی‌دهد

بررسی کنید:

```bash
curl -I http://127.0.0.1:31080/
apache2ctl configtest
curl -I https://your-panel-hostname.example/
```

همچنین DNS و حالت SSL کلادفلر را بررسی کنید.

### اتصال پنل موفق است ولی اینباندها برای نماینده نمایش داده نمی‌شوند

یک‌بار تب **نماینده‌ها** را ببندید و دوباره باز کنید؛ نسخه‌های فعلی هنگام ورود به این تب `/api/admin/inbounds` را دوباره می‌خوانند. اگر هنوز خالی است، پنل 3x-ui ذخیره‌شده را از **تنظیمات / پنل‌ها** تست کنید و لاگ کانتینر داشبورد را ببینید.

### تداخل پورت

نصب‌کننده مالک `APP_PORT` را نمی‌کشد. پورت loopback دیگری انتخاب کنید:

```bash
APP_PORT=31081 bash <(curl -fsSL https://raw.githubusercontent.com/DashSaman/PVNetwork-Reseller-Dashboard/main/install.sh)
```

### لاگ‌ها

```bash
docker logs -f pv-reseller-dashboard
```

## نصب‌کننده قدیمی full-stack

نصب‌کننده قدیمی که Caddy و 3x-ui/Xray محلی می‌ساخت فقط برای استفاده تاریخی/دستی نگه داشته شده:

```text
scripts/install-full-stack-legacy.sh
```

این همان نصب‌کننده‌ای نیست که دستور یک‌خطی بالا اجرا می‌کند.

## توسعه

ایمج production از `docker/Dockerfile` ساخته می‌شود — مراحل وابستگی/بیلد با Bun و ران‌تایم با Node.js. Prisma از SQLite برای وضعیت داشبورد استفاده می‌کند.

بررسی‌های مفید قبل از انتشار:

```bash
bash scripts/test-dashboard-installer.sh
node scripts/test-inbound-refresh.mjs
bash -n install.sh
bash -n update.sh
```
