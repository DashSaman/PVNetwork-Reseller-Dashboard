# آمار تخصیص و مصرف و اصلاح نشست داشبورد

## رفتار و علت خطای ورود

در بررسی ۱۸ اکتبر، تب باز مرورگر هنوز نمای ادمین را نگه داشته بود، ولی نشست
معتبر نبود. درخواست داشبورد 401 می‌گرفت و UI آن را به اشتباه خرابی اتصال سرویس
نمایش می‌داد. بارگذاری مجدد همان تب صفحهٔ ورود را نشان داد؛ بررسی مستقل با نشست
معتبر از آدرس عمومی، اتصال ONLINE و مصرف زندهٔ کاربران را تأیید کرد.

کلاینت اکنون با 401 مسیرهای ادمین/نماینده، نشست واقعی را دوباره می‌خواند؛ نشست
منقضی به ورود و تغییر حساب به نمای درست هدایت می‌شود. بررسی نشست هم‌زمان تک‌درخواست
است و پاسخ قدیمی، ورود تازه را بازنویسی نمی‌کند. فعال‌شدن تب نیز نشست را بررسی
می‌کند. پاسخ auth/me کش نمی‌شود. خطای شبکه، 403 یا خطای سرویس به‌تنهایی باعث خروج
نمی‌شود؛ 401 نیز وضعیت سرویس را OFFLINE نمی‌کند. مدت اعتبار/امضای نشست تغییر نکرد.

## معنی اعداد حجم

- سهمیهٔ نماینده: مقدار trafficPoolGB؛ صفر در مدل فعلی یعنی نامحدود.
- سهمیهٔ کاربران فعلی: جمع trafficGB کاربران تحت مالکیت نماینده، یک‌بار برای هر
  کاربر؛ تعداد کاربران نامحدود جداست. این عدد، مبلغ فروش یا تاریخچهٔ فروش مادام‌العمر نیست.
- باقی‌ماندهٔ تخصیص‌نیافته: بیشینهٔ صفر و سهمیهٔ نماینده منهای سهمیهٔ کاربران،
  مصرف قطعی تاریخی حذف/ریست و رزرو عملیات فعال CREATE/UPDATE.
- مصرف واقعی: شمارندهٔ کاربران متعلق به همین سامانه؛ داخل هر پنل بیشینهٔ نسخه‌های
  اینباند، بین پنل‌های مرجع جمع، با استفاده از canonicalUserUsage موجود.
- فروش مصرف‌نشده: جمع بیشینهٔ صفر و سهمیهٔ هر کاربر منهای مصرف همان کاربر.
  این مقدار داخل سهمیهٔ کاربران است و دوباره از موجودی کسر نمی‌شود.

overview همچنان فقط DB محلی را می‌خواند. panel-summary از snapshot مشترک آمار
زنده استفاده می‌کند. نبود snapshot تازه، اینباند مرجع، کاربر یا شمارندهٔ عددی معتبر
باعث مقدار null/«نامشخص» می‌شود، نه مصرف صفر. نامحدود نیز عدد صفر مصرف‌نشده نیست.
آمار کل زیرساخت جداگانه برچسب دارد و مبنای فروش/موجودی نماینده نیست.

## نمایش نام زیرساخت

نام تنظیم‌شدهٔ سرویس بالادست از متادیتای bootstrap، لوکیشن‌ها، نمودارها و لینک‌های
مستقیم نماینده حذف می‌شود. خطاهای اتصال نماینده نام/پیام خام بالادست را نشان نمی‌دهند.
نام عمومی «سرویس» است؛ عنوان قابل‌نمایش لوکیشن از نام زیرساخت پاک می‌شود. شناسه‌ها،
هاست/پورت اتصال، تنظیمات ذخیره‌شده، دسترسی‌ها و کلیدهای کاربران تغییر نکرده‌اند.
واژگان رابط نماینده و راهنمای ربات نیز به نام محصول و API سازگار اشاره می‌کنند.
تنظیمات فنی ادمین برای مدیریت اتصال همچنان در اختیار ادمین است.

## بررسی نسخه

- تست‌های واحد مرتبط: ۳۰ موفق؛ شامل حسابداری، همگام‌سازی، کش، کلید بکاپ،
  انقضای نشست و حذف نام سرویس از متادیتا.
- fixture مستقل API و مرورگر: ۱۸ بررسی موفق؛ آمار محلی و زنده، پاسخ کند، نبود داده،
  حفظ مقادیر ناشناخته، نمایش موبایل، خروج پس از انقضا و تغییر نقش واقعی نشست.
- تست Python بکاپ/بازیابی: ۲۰ تست، ۱۹ موفق و یک skip مربوط به symlink در Windows.
- TypeScript، ESLint مسیرهای تغییرکرده و build محلی موفق.
- image نهایی Docker با Next.js 16.1.3 نیز build شد. ۹ بررسی روی همان image،
  در کانتینر network=none بدون پورت منتشرشده یا mount دادهٔ واقعی موفق بود:
  آمار محلی، مصرف کانونی چندپنلی، حذف نام زیرساخت از پنج پاسخ نماینده و رد دسترسی
  ادمین بدون نشست. سرویس ساختگی بالادست صفر درخواست نوشتن دریافت کرد.

تست‌ها از دادهٔ ساختگی و سرویس آزمایشی محلی استفاده می‌کنند. اطلاعات واقعی کاربران
و مدارک خصوصی سرور در ریپو قرار نمی‌گیرند. روش انتقال در
[راهنمای بازیابی](dashboard-migration-restore.fa.md) است.
